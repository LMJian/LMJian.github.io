# 订单取消预测：从 CSV 到 HTTP 接口

配套文章：《后端工程师的机器学习入门：从业务问题到可运行的预测模型》。这是一个可在本机运行的教学项目。

## 快速运行

使用 Python 3.12。下面命令适用于 macOS / Linux，请先进入本目录：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python train.py
python predict.py
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

另开终端发送请求：

```bash
curl -sS http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{"amount":500.0,"account_days":30,"past_cancels":2,"payment_channel":"wechat"}'
```

返回取消概率估计、验证集选出的阈值、预测类别和模型版本。按 Ctrl+C 停止服务，再运行最后一条启动命令，仍会使用同一个模型。

Windows PowerShell 可用 `py -3.12 -m venv .venv` 和 `.venv\Scripts\Activate.ps1` 创建、激活环境，其余 Python 命令相同。

## 数据约定

`orders.csv` 是由 `generate_data.py` 生成的 3000 条**合成订单**，没有真实用户数据。它模拟已完成标签观察的订单，每行独立生成。金额、注册天数、支付渠道包含少量缺失值；标签完整。

| 字段 | 含义 | 是否输入模型 |
|---|---|---|
| order_id | 教学订单唯一编号 | 否，只用于检查重复 |
| amount | 下单金额，单位元，非负 | 是 |
| account_days | 下单时注册天数，非负整数 | 是 |
| past_cancels | 下单前 30 天取消次数，非负整数 | 是 |
| payment_channel | 下单时已知的所选支付渠道 | 是 |
| cancelled | 下单后 24 小时内是否取消，0 或 1 | 否，这是标签 |

真实业务中，特征必须来自下单时可用的信息，负类需完整观察 24 小时。这份 CSV 没有真实时间轴，不能验证时间切分、标签延迟或线上效果。如果你的产品下单时尚不知道支付渠道，应删除该字段或调整预测时点。

运行 `python generate_data.py` 可以重新生成相同数据（覆盖本目录的 `orders.csv`）。不要对替换后的真实数据执行该命令。

## 训练与推理约定

- 60% 训练集：包含预处理的整条 Pipeline 做 5 折交叉验证，在 6 组超参数中选取 ROC-AUC 最优的一组，并在这 60% 数据上重训。
- 20% 验证集：从 0.10 到 0.90、间隔 0.05 的候选中选择 F1 最高的阈值。并列时选择较小阈值。
- 20% 测试集：方案确定后评估一次。不要根据输出反复修改方案再报告同一测试集结果。
- `model.joblib` 保存预处理、模型、阈值、特征顺序、版本、数据摘要和评估记录；`evaluation.json` 单独保存评估结果。这两个文件由训练生成，不随项目分发。
- `predict.py` 在独立进程中加载该文件；`app.py` 每个服务进程启动时加载一次，请求中不训练、不重新拟合预处理。
- HTTP 请求必须提供四个特征字段，可以用 `null` 表示暂缺（但不能全部为 null）。字段缺失、额外字段、负数、非法类型、非有限数值会返回 422。未见过的非空渠道名称允许通过；独热编码全零不代表模型学会了新渠道。

CSV 的空白单元格由 pandas 读成缺失值；CSV 整数列含空值后可能成为浮点列，因此读取时允许把 30.0 转回整数。HTTP 输入严格校验，天数和次数应传 JSON 整数。

`class_weight="balanced"` 会改变训练中两类样本的权重，输出不能自动视为经过校准的真实概率。示例用 F1 选阈值只是教学选择，实际项目应结合误报、漏报和后续干预成本。

仅加载自己训练或确认可信的 joblib 文件：它使用的反序列化机制可以执行代码。训练与推理使用相同依赖版本；升级依赖时应重新验证或训练模型。

## 验证

在已激活的环境中运行：

```bash
python test_demo.py
```

验证在临时目录中训练，检查独立进程加载、HTTP 正常/异常输入、服务重启后的预测一致性；不会覆盖本目录中的模型。验证会临时启动仅监听 `127.0.0.1` 的服务。

模型来自人为设置的概率规律。这里的测试证明程序可以运行、输入处理一致，不证明模型在真实业务中有效。上线前还需基于真实数据验证、做好特征获取、超时降级、访问控制和监控。
