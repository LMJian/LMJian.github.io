# 中国年度调休数据

卷轴读取公开静态文件，不向本站上传闹钟设置或个人日程。官方通知是日期依据，本站负责将通知整理成可校验的 JSON。当前发布内容为国办发明电〔2025〕7号对应的 2026 年安排。

文件入口为 `https://lmjian.github.io/assets/holidays/cn/index.json`。年度文件与博客一起由现有 GitHub Actions 构建并发布。客户端首次安装使用随 App 打包的数据，后续下载校验通过的更高版本；网络失败不清除旧数据。

本站仅托管静态 JSON，不提供下载说明网页，也不在首页、导航、搜索、站点地图或文章中添加入口。本文位于 Jekyll 不发布的 `_docs` 目录，仅供仓库维护者阅读。客户端直接访问 JSON URL。

## 文件约定

`index.json` 包含 `schemaVersion: 1`、`region: "CN"` 和 `years` 数组。每个年度条目包含 `year`、正整数 `revision`、相对文件名 `file` 和文件原始字节的 `sha256`。同一索引每年只保留一个当前版本。

年度文件使用 `YYYY.vN.json`。字段包括：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 当前为 1；未知协议应拒绝更新 |
| `region` | 当前为 CN |
| `year` / `revision` | 公历年份与单调递增的数据版本 |
| `timeZone` | Asia/Shanghai；日期和闹钟均按北京时间解释 |
| `source` | 官方通知标题、HTTPS 原文地址、成文日期 |
| `overrides` | 逐日的 `date`、`kind` 和 `name`；`rest` 为休息、`work` 为补班 |

年份内没有出现在 `overrides` 的日期按普通周一至周五工作日判断。缺少年度文件表示该年度安排未知，不能将其解释为空的调休表。个人请假、公司排班和用户单日修改属于客户端设置，不写入公开年度文件。

索引最大 64 KiB，年度文件最大 128 KiB。客户端只允许在当前目录下载文件，校验 SHA-256、协议、年度、版本、日期有效性和重复日期。校验失败保留原数据，并显示更新失败。SHA-256 用来发现传输或发布内容不一致，下载来源的身份由 HTTPS 提供。

## 发布或更正

1. 对照国务院办公厅通知核对每个休息日和补班日。
2. 新年度添加 `YYYY.v1.json`；更正添加新版本，保留已发布的旧文件。
3. 用新文件的原始字节计算 SHA-256，再更新 `index.json` 中对应年度的条目。
4. 运行 `python3 scripts/check_holidays.py` 和 `bundle exec ruby scripts/check_holiday_isolation.rb`，检查数据和网页隔离。新增年度时在检查脚本中增加依据官方通知独立整理的预期日期。
5. 推送到 `main`，等待 Pages 构建和部署成功。
6. 下载线上索引和年度文件，核对哈希及日期，再报告发布成功。

不要提前填写尚未核实的下一年度安排。客户端只对已安装年度展示“调休数据已就绪”。发布完成也不表示所有离线设备已更新；客户端下一次成功检查时才会取得新版本。Pages 使用缓存，客户端应重新验证索引，新版本年度文件使用新 URL。

## 维护边界

年度数据发布会触发整个博客的构建。构建失败时，新数据不会上线，客户端仍使用旧数据。本站文件是公开数据，任何人均可读取。客户端应保留内置数据和有效缓存，不应把下载成功作为每次响铃的前提。
